[[sec-interfaces]]
== Interfaces

This chapter specifies the external interfaces: the wire protocol and the
configuration limits. It is the contract between the server and its clients.

=== Wire protocol

The server speaks newline-delimited JSON over TCP. Values are base64
encoded so arbitrary bytes survive the JSON framing. Requests and effects:

[[tab-wire]]
.Wire requests (see ADR-004 for rationale).
[cols="1,3,2",options="header"]
|===
|Request |Payload |Effect

|`put`
|`{"op":"put","key":"...","value":"<base64>"}`
|Stage write; acknowledged at the next `sync`

|`get`
|`{"op":"get","key":"..."}`
|Snapshot read; missing keys return not-found

|`delete`
|`{"op":"delete","key":"..."}`
|Stage tombstone; acknowledged at the next `sync`

|`scan`
|`{"op":"scan","start":"...","end":"...","limit":N}`
|Ordered range read up to `limit` entries

|`sync`
|`{"op":"sync"}`
|Persist the staged prefix; defines the acknowledgement point

|`flush`
|`{"op":"flush"}`
|Force memtable flush into a manifest-published table

|`compact`
|`{"op":"compact"}`
|Force a merge of live tables

|`stats`
|`{"op":"stats"}`
|Return table counts, record counts, and byte totals
|===

Malformed input is rejected and the connection survives; see
<<sec-verification>> for the wire gate tests.

TIP: Batch many `put` requests behind a single `sync`. Acknowledgement is
a prefix property, so one `sync` covers every write before it.

=== Configuration limits

Keys and values are arbitrary bytes subject to `fig-core::Config::Limits`
(maximum key length, maximum value length, scan limit enforcement). Limits
are validated at the API boundary: oversized inputs are rejected before
they reach the log.
